# 맥미니 홈서버: 카카오·네이버 로그인과 로컬 AI

## 현재 준비된 것과 남은 것

`npm start`는 기존 브라우저 체험판을 유지합니다. `npm run start:home`은 같은 디자인에 실제 OAuth 인증, 서버 저장, 로컬 AI 상담을 연결합니다. 이 두 모드의 계정 데이터는 별개이며 테스트 계정을 실제 계정으로 이전하지 않습니다. 홈서버 모드는 결제와 유료 상품 구매를 비활성화합니다.

구현: 카카오·네이버 로그인/명시적 계정 연동, 서버 SQLite 계정·프로필·운세·상담 저장, HttpOnly 쿠키, 로그인 시 세션 교체, OAuth state 검증, CSRF 검증, 로그아웃, 계정 삭제, 한국 시간 하루 1회 상담, AI 실패 시 횟수 유지, 동시 AI 요청 1건 제한.

아직 실제 검증이 필요한 것: 개발자 앱 등록, 실제 소셜 로그인, 실제 모델 답변의 다양한 질문별 품질·부하 성능, 도메인과 HTTPS 터널, 맥 재시작 후 자동 실행. 자동 테스트는 소셜 서비스와 AI 응답을 모의합니다. 테스트 통과가 실제 공급자 인증 성공이나 공개 서비스 출시 완료를 뜻하지 않습니다.

## 이번 맥에서 확인한 결과

Ollama 0.34.4와 Qwen3 8B 설치 및 모델 다운로드를 완료했습니다. 실제 로컬 API에 가상의 만세력과 이직 질문을 보내 한국어 답변을 받았습니다. 초기 요청은 47.89초, 해석 근거를 보완한 요청은 36.76초였습니다. 서로 입력과 모델 로딩 상태가 달라 성능 개선 비교는 아니며 사용자별 속도나 공개 서비스 처리량을 보장하지 않습니다. 초기 응답의 근거 없는 오행 강약 설명을 발견해 기존 엔진의 해석·조언을 명시적으로 전달하고 새 판정을 만들지 않도록 프롬프트를 보완했습니다. 다양한 질문의 품질 검증은 남아 있습니다. 마지막 가상 입력/출력은 Git에서 제외되는 `data/home/ai-smoke.json`에 저장됩니다.

Safari에서 홈서버 페이지, 카카오·네이버 로그인 선택과 앱 설정 미완료 안내를 확인했습니다. 서버는 `http://127.0.0.1:3000`에서 응답하고 웹서버/Ollama의 로그인 시 자동 실행을 등록했습니다.

## 1. 로컬 실행

Node.js 22.13 이상이 필요합니다. 현재 작업 환경에는 Node가 있습니다. `.env`가 없을 때만 아래 복사를 실행하고, 기존 파일이 있으면 새 홈서버 항목을 추가하세요.

```bash
cp .env.example .env
npm run start:home
```

`http://127.0.0.1:3000`을 여세요. `localhost`가 아닌 이 주소를 일관되게 사용합니다. 아직 앱 키를 입력하지 않았다면 실제 로그인은 진행되지 않습니다. `.env`는 Git에서 제외되고 웹서버가 제공하지 않습니다.

## 2. Ollama와 첫 모델

[Ollama macOS 설치](https://ollama.com/download/mac) 후 앱을 실행합니다. 24GB 맥에서는 시작 후보로 `qwen3:8b`를 선택했습니다. [공식 모델 페이지](https://ollama.com/library/qwen3:8b) 기준 Q4_K_M 다운로드는 약 5.2GB이며 실행 시에는 문맥과 캐시 등 추가 메모리가 필요합니다. 실제 속도와 한국어 품질은 이 맥에서 측정해야 합니다.

```bash
ollama pull qwen3:8b
ollama run qwen3:8b
```

대화에서 `/bye`로 나옵니다. `.env`에 다음 값을 사용합니다.

```dotenv
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
```

서버는 기존 만세력 코드를 다시 실행해서 계산한 기둥과 해석 근거만 AI에 전달합니다. 브라우저가 보내는 기둥이나 해석을 계산 근거로 신뢰하지 않습니다. 상담 요청은 12,288 문맥 토큰, 최대 900 생성 토큰, 600초 제한이며 추론 모드를 끕니다. AI 상담은 먼저 실제 출력 사례를 확인한 뒤 공개하세요. 프롬프트의 지침만으로 답변 품질을 보장할 수는 없습니다. [Ollama API](https://docs.ollama.com/api/chat)

Ollama의 포트 11434는 공개하지 않습니다. 외부 접속은 아래 웹서버 3000번으로만 연결합니다.

## 3. 도메인과 HTTPS

도메인을 구매하고 Cloudflare에 연결한 뒤 Cloudflare Tunnel에서 공개 호스트 이름을 등록합니다. 예를 들어 `saju.example.com`을 `http://127.0.0.1:3000`으로 연결합니다. 실제 도메인을 정하기 전 예시 주소를 등록하지 마세요.

[Cloudflare 공식 터널 설정](https://developers.cloudflare.com/tunnel/get-started/)에서 macOS 커넥터 설치와 실행 명령을 안내합니다. 터널 토큰은 비밀 값이므로 `.env`와 마찬가지로 채팅이나 저장소에 올리지 않습니다. 임시 Quick Tunnel 주소는 고정 OAuth 콜백 주소로 쓰지 않습니다.

공개 연결 전에 `.env`를 변경하고 서버를 재시작하세요.

```dotenv
NODE_ENV=production
PUBLIC_ORIGIN=https://saju.example.com
PORT=3000
```

공개 모드는 HTTPS 주소를 요구하고 Secure 쿠키를 사용합니다. 서버는 127.0.0.1에만 바인딩합니다. 공유기 포트 포워딩 없이 터널로 연결할 수 있습니다. 로그인과 상담 요청에 캐시를 적용하지 마세요.

## 4. 카카오 앱 등록

[카카오 디벨로퍼스](https://developers.kakao.com/)에서 앱을 생성하고 카카오 로그인을 활성화합니다. 실제 서비스 주소와 아래 Redirect URI를 등록합니다.

```text
https://실제도메인/auth/kakao/callback
```

서버 설정:

```dotenv
KAKAO_CLIENT_ID=REST_API_키
KAKAO_CLIENT_SECRET=클라이언트_시크릿
```

카카오의 클라이언트 시크릿을 설정하고 해당 값을 서버에 입력합니다. 이 구현은 두 값이 모두 있어야 카카오 로그인을 활성화합니다. 닉네임은 제공될 때만 사용하며 이메일을 계정 합치기 기준으로 사용하지 않습니다. 필요한 서비스 설정·동의 항목은 콘솔에서 확인하세요. [공식 REST 로그인 절차](https://developers.kakao.com/docs/ko/kakaologin/rest-api)

로컬 테스트가 가능한 앱 설정에서는 `http://127.0.0.1:3000/auth/kakao/callback`도 등록합니다. 공급자 콘솔이 허용하는 주소 정책을 확인하고 로컬 콜백이 허용되지 않으면 HTTPS 도메인에서 검증합니다.

## 5. 네이버 앱 등록

[네이버 개발자센터](https://developers.naver.com/apps/#/register)에서 네이버 로그인 앱을 등록합니다. 서비스 URL은 `https://실제도메인`, Callback URL은 아래 주소입니다.

```text
https://실제도메인/auth/naver/callback
```

```dotenv
NAVER_CLIENT_ID=클라이언트_ID
NAVER_CLIENT_SECRET=클라이언트_시크릿
```

[네이버 로그인 개발가이드](https://developers.naver.com/docs/login/devguide/devguide.md)에 따라 실제 서비스 화면과 공개 이용에 필요한 검수 절차를 진행합니다. 개발 중 테스트 사용자 범위와 일반 사용자 공개 가능 상태를 콘솔에서 확인하세요. 닉네임/이름은 제공될 때만 사용합니다. 로컬 주소가 허용되면 `http://127.0.0.1:3000/auth/naver/callback`을 추가합니다.

두 앱 등록 후 서버를 재시작합니다. 먼저 카카오로 로그인하고 마이페이지의 네이버 연동으로 같은 계정에 묶습니다. 별도로 로그인해 서로 다른 계정이 된 경우 자동 합치지 않습니다.

## 6. 맥 자동 실행

이번 세션에서 자동 등록한 파일은 `~/Library/LaunchAgents/com.sai.home.plist`입니다. 수동으로 설치하는 경우 `deploy/com.sai.home.plist.example`의 `NODE_ABSOLUTE_PATH`를 `command -v node` 결과로, `PROJECT_ABSOLUTE_PATH`를 프로젝트 절대 경로로 교체합니다. 로그 폴더 `data/home`을 먼저 만들고 다음 위치로 복사합니다.

```text
~/Library/LaunchAgents/com.sai.home.plist
```

LaunchAgent 등록과 로그 확인:

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.sai.home.plist
launchctl kickstart -k gui/$(id -u)/com.sai.home
```

이는 사용자 로그인 후 실행되는 설정입니다. FileVault가 켜져 있으면 재부팅 후 잠금 해제를 포함한 운영 절차가 필요합니다. 24시간 서비스에서는 시스템 잠자기를 끄고, 디스플레이만 꺼지도록 설정합니다. Ollama 앱도 로그인 시 실행하도록 설정하고, Cloudflare 터널은 [macOS 서비스 문서](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/as-a-service/macos/)를 따라 별도로 실행합니다. 이번 구축에서는 Homebrew Ollama와 Qwen3 8B를 설치했고, Ollama와 웹서버 LaunchAgent를 등록했습니다. 웹서버 정상 응답을 확인했습니다. 잠자기 설정은 변경하지 않았고 재부팅 후 실행은 아직 확인하지 않았습니다. 다음에 재설치하려면 `node deploy/install-home-service.js`를 사용합니다. 기존 LaunchAgent가 있으면 덮어쓰지 않고 중단합니다.

## 7. 실제 공개 전 확인

다른 브라우저에서 두 공급자의 실제 로그인·로그아웃·계정 연동·탈퇴와 일일 상담 제한을 확인합니다. 서버 재시작 후에도 프로필과 기록이 남는지 확인합니다. AI 모델이 없는 상태와 두 사람이 동시에 요청하는 상태에서 안내가 표시되는지 확인합니다.

SQLite는 `data/home/sai.sqlite`에 저장됩니다. WAL 사용 중 파일 하나만 복사하지 말고 SQLite 온라인 백업을 사용하거나 서버를 멈춘 뒤 데이터 폴더를 백업하세요. 백업의 개인정보도 관리하고 복원 시 삭제했던 계정이 되살아나지 않도록 운영 정책을 정하세요. 현재 공개 요청 제한은 연결 주소당 분당 120건으로, 터널에서는 사용자별이 아닌 커넥터 전체에 걸릴 수 있습니다. 실제 트래픽을 측정하고 Cloudflare 쪽 사용자별 제한과 함께 조정하세요. 서버 프로세스는 하나만 운영하세요. 동시 AI 처리는 1건이고 다른 요청에는 재시도 안내를 반환합니다.

운영자 연락처, 수집하는 출생 정보와 상담 내용의 용도·보관·삭제 설명 등 실제 서비스 고지를 준비하세요. 사이트/HTTPS 연결은 터널 제공자를 거치며 ‘로컬 AI’가 인터넷 전체 경로의 비공개를 뜻하지는 않습니다.

```bash
npm test
```

## 전체 사주 해석의 로컬 AI 전환

이제 `npm start`도 홈서버를 실행합니다. 과거 브라우저 규칙 체험판은 `npm run start:demo`로만 실행합니다. 홈서버 화면에서 월별 주제 카드·대화 질문·짧은 미리보기와 선택한 상세 해석 항목·오늘의 운세·상담·사주·궁합·대운·연운·택일의 해석 문장은 모두 로컬 LLM이 작성합니다. 만세력 간지·십성·오행 개수·대운 배열·택일 후보 날짜와 표는 검증 가능한 기존 계산 코드를 사용합니다. 운영 안내·FAQ·버튼 문구는 고정된 서비스 설명입니다.

상세보기는 버튼을 눌렀을 때 생성합니다. AI가 실패하거나 응답 구조가 잘못되면 오류와 재시도 안내를 표시하고 규칙 기반 해석으로 대체하지 않습니다. Ollama의 JSON 스키마 출력 후 서버가 응답 항목과 문장 구조를 검증합니다. [공식 구조화 출력 문서](https://docs.ollama.com/capabilities/structured-outputs)

일반 해석은 소셜 로그인 없이 실행되므로 앱 키를 등록하기 전에도 상세보기를 확인할 수 있습니다. 오늘의 운세·일일 상담과 영구 프로필 저장에는 로그인이 필요합니다. 유료 결제는 계속 비활성화되어 있고 상품 해석 메뉴는 현재 무료 AI 결과를 제공합니다.

성공한 해석은 SQLite `generated` 테이블에 브라우저 세션별로 하루 보관하고 동일한 모델·프롬프트 버전·출생 정보·기간·조건의 요청에 재사용합니다. 로그아웃/로그인 시 세션이 교체되면 해당 세션 캐시를 삭제합니다. 만료 데이터는 다음 API 요청에서 정리합니다. 다른 사용자의 캐시를 공유하지 않습니다. 모든 종류는 하나의 AI 실행 제한을 공유합니다. 최대 생성 시간은 600초, 문맥은 12,288토큰이고 상세보기의 출력 제한은 4,200토큰입니다. 모델이나 문맥 길이를 바꾸면 다시 메모리·응답 시간을 측정하세요.

### 최종 전환 검증 결과

가상 출생 정보(2000-06-15 09:30)를 사용해 최종 작성 기준 `all-local-v3`의 주제별 요약 20문장과 상세 요약 30문장·12개 항목이 실제 Ollama에서 생성되어 Safari에 표시되는 것을 확인했습니다. 최종 요약 요청은 약 2분 17초, 상세 요청은 약 4분 48초 걸렸습니다. 상세보기를 닫았다가 다시 열면 생성 없이 즉시 표시됩니다. 이 수치는 단일 사례이며 공개 서비스 처리량을 의미하지 않습니다. 긴 답변의 생성 속도는 추후 모델/실행 방식 비교가 필요합니다.

초기 실기 검증에서 작성 지시문을 질문 필드에 복사하거나 요약 문장을 반복한 응답을 확인해, 작업 지시를 system 메시지에서 명시하고 질문 필드·문장 길이·요약 중복 검증을 추가했습니다. 실패 결과를 기존 규칙 문장으로 바꾸지 않습니다. 전체 자동 테스트 39개가 통과했습니다. 실제 공급자 로그인이 없는 상태에서 운세·상담의 화면 흐름은 아직 검증하지 못했으며 해당 API는 모의 공급자/모델 응답으로 검증했습니다.

### 짧은 답변과 실시간 표시 (local-fast-v4)

Qwen3 8B Q4 모델을 유지합니다. 월별 첫 화면은 최대 40자씩 핵심 3문장이고, 월별 주제 및 상세 항목은 클릭할 때만 별도 생성합니다. 사주·대운·연운·택일도 처음에는 3문장만 생성하고 항목별로 열어봅니다. 만세력 계산과 항목 목록에는 LLM을 호출하지 않습니다.

Ollama의 NDJSON 출력을 서버와 브라우저가 실시간으로 전달합니다. 초안은 텍스트로만 표시하고, 완료 이벤트와 형식 검증을 통과한 결과만 세션별 SQLite 캐시에 24시간 저장합니다. 생성 실패·중단 시 초안을 완료된 결과로 저장하지 않습니다. 로그인 후 운세·상담은 기존 일별 보관 및 이용 횟수 규칙을 유지합니다. 다른 브라우저 세션에는 결과를 공유하지 않습니다. 같은 요청이 동시에 들어오면 한 번만 생성하고 실시간 출력을 함께 전달합니다. 서로 다른 AI 요청은 기존 한 번에 한 요청 제한을 유지합니다.

가상 출생 정보로 한 차례 측정: 월별 첫 토큰 6.16초 / 첫 문장 완성 7.65초 / 완료 11.45초, 상세 한 항목 첫 토큰 1.13초 / 첫 문장 완성 3.89초 / 완료 9.68초, 월별 캐시 재요청 0.005초. 평균이나 동시 접속 성능 보장이 아닙니다. `node scripts/benchmark-fast-ai.js`로 실행 중인 홈서버를 다시 측정할 수 있습니다. 이전 all-local-v3 측정은 긴 답변 구조의 기록입니다. 외부 API는 사용하지 않습니다.

### 사용자 지정 전문 분석 지침 (expert-v6)

`backend/prompts/saju-expert.txt`에 사용자가 제공한 프롬프트 원문을 저장하고 명시적으로 요청한 상세 항목의 system 메시지로 그대로 사용합니다. 빠른 미리보기에는 별도의 짧은 지침을 사용합니다. 프롬프트 해시를 캐시 버전에 포함하므로 원문이 바뀌면 이전 생성 결과를 재사용하지 않습니다. 추가 메시지는 요청한 항목, JSON 출력 형식, 실제 제공 자료의 종류 및 누락 정보를 전달합니다. 이미지가 제공되지 않은 현재 서비스에서는 캡처를 판독했다고 주장하지 않고 계산된 만세력 데이터만 전달합니다. 캡처 업로드·이미지 판독 기능은 포함하지 않습니다.

상세보기는 원문의 12단계 순서를 사용합니다. 각 상세 항목은 각 문단 최소 80자, 최소 3문단, 최대 24문단의 상세 출력을 허용하고 출력 한도를 5,000토큰으로 늘렸습니다. 현재 최초 미리보기와 주제 아이콘은 속도 개선을 위한 짧은 한 문장입니다. 긴 상세 해석에는 이전의 10초대 측정이 적용되지 않으며 항목별 실시간 표시와 하루 동안 결과 재사용을 유지합니다. 답변이 토큰 한도로 중단되면 완료된 결과로 저장하지 않습니다.

이전 규칙 엔진의 성격·조언·해석 문장은 Qwen의 분석 근거로 전달하지 않습니다. 출생 정보, 기둥별 십성·지장간·12운성, 표시된 오행 개수, 대운 배열, 연별 간지와 생일 전후 만 나이 범위를 전달합니다. 오행 개수를 신강/신약 확정값으로 취급하지 않습니다. 출생지·시각 정확도·신살·귀인 및 확정된 용신 등 계산되지 않은 정보는 누락으로 표시합니다. 이 지침은 답변 방식과 분량을 변경하며 모델 해석의 사실성이나 명리학적 정확도를 보장하지 않습니다.

대운 시작 오프셋은 배열 대신 years/months/days 단위를 가진 startAfterBirth로 전달합니다. 대운 나이는 세는나이와 생일 전후 만 나이 범위를 구분합니다. 실제 Qwen 검증에서는 상세 한 항목이 3문단·약 1,240자로 약 70초에 완료되었습니다. 이 측정은 자료 단위 표기 개선 전 단일 사례이며 사실성 검증이나 평균 속도가 아닙니다.

### 빠른 아이콘 미리보기 (fast-preview-v8)

월별 첫 화면, 주제 아이콘, 오늘의 운세·상담 및 상품의 최초 미리보기는 한 문장, 최대 24자, 출력 한도 96토큰으로 제공합니다. 원문 전체를 넣었던 긴 입력과 생애 자료는 이 경로에서 제외하고 간단한 계산 근거 및 짧은 출력 지침을 사용합니다. 긴 전문 프롬프트는 상세 항목 요청에만 사용합니다. 원문과 미리보기 지침 해시를 캐시 버전에 포함합니다.

만세력 그림 아이콘은 계산표만 열고 해석 요청을 하지 않습니다. ‘상세내용 보러가기’에서 보고서 목록을 열고, 그 안에서 선택한 항목만 장문 생성합니다. 나머지 주제 그림은 짧은 미리보기만 요청합니다.

서버 시작 시 Qwen을 미리 불러오고 Ollama keep_alive를 24시간으로 설정합니다. 모델을 바꾸거나 외부 API를 사용하지 않습니다. 실제 가상 정보 단일 측정: 월별 미리보기 완료 2.08초, 연애·일·건강 아이콘 완료 1.61~1.66초, 캐시 반환 0.014초. 모델이 준비된 상태에서 측정한 값이며 모델 최초 로딩·다른 생성 요청·동시 접속 및 장문 보고서에 대해 5초를 보장하지 않습니다.
