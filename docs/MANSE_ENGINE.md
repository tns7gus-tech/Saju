# 만세력 자체 생성: 조사 결과와 구현 설계

2026-09-25 기준. 사용자 제공 캡처는 개인의 생년월일시와 이름이 들어 있으므로 이 문서와 공개 저장소에는 원본 이미지나 개인별 검증 입력값을 넣지 않는다.

## 캡처에 보이는 출력값

| 표시 | 계산에 필요한 입력/규칙 |
| --- | --- |
| 양력 생년월일시, 성별, 나이 | 양력/음력·윤달 구분, 출생 시각, 성별, 나이 표시 방식 |
| 년·월·일·시 네 기둥 | 양음력 변환, 입춘과 절기 **시각**, 일진의 60갑자, 시지 2시간 구간과 시간 |
| 십성·지장간·12운성·오행 | 일간을 기준으로 한 명리 대응표; 화면의 오행 개수는 네 기둥의 8글자 합계 |
| 합·충·형·파·해, 공망, 신살·귀인 | 명리 규칙표와 유파별 표시 기준. 천문 데이터 API 응답에 들어 있지 않음 |
| 대운 시작 나이, 순·역행, 10년 구간 | 성별 및 출생년 천간 음양, 출생 시각과 전후 절입 시각의 차이, 대운수 반올림/표시 기준 |
| 2026 세운, 월별 운 | 연간·월간 간지의 연속 계산과 선택한 연도·월; 월 경계는 양력 매월 1일이 아닌 절입 시각으로 판정 |
| 이미지 카드 | 계산된 JSON을 HTML/CSS·SVG/Canvas로 화면에 렌더하고 PNG로 저장. AI가 이미지를 그릴 필요는 없음 |

첨부 화면에 `전통나이`와 `만나이로 변경은 설정화면에서`라는 문구가 있으므로, 나이는 UI 설정이며 명식의 계산 결과와 분리한다. 다섯 사례 모두 시작 대운의 순·역행과 정수 `대운수`가 표시된다. 시작 나이를 정수로 반올림하는 방식과 정확한 대운 시작 일시가 같은 개념은 아니다.

## 데이터 흐름

1. **입력:** 출생 날짜·시각, 양/음력, 윤달, 출생 장소와 시간대, 시각의 정확도, 전통적 대운 방향 계산에 필요한 선택값을 받는다. 상대의 출생정보는 당사자 동의가 있을 때만 받는다.
2. **역법:** 음력 입력을 양력 시각으로 변환한다. 입춘을 기준으로 년주를, 월을 시작하는 12절의 정확한 절입 시각으로 월주를, 연속된 60갑자 일수로 일주를, 시각 구간과 일간으로 시주를 정한다. 입춘과 다른 절기 근처, 23:00~01:00, 일광절약시간과 과거 표준시에는 규칙을 고정해서 재검증한다.
3. **파생:** 일간을 기준으로 십성, 지장간 십성, 오행, 12운성, 공망, 합충 등 규칙표를 적용한다. 신살·귀인과 용신/신강 판정은 계산과 해석의 유파 차이가 있으므로 독립 모듈로 분리한다. `용신`은 날짜만으로 유일하게 확정되는 천문값이 아니다.
4. **운 흐름:** 대운 순/역을 정하고 다음/이전 절기까지의 시간 차를 설정한 환산 방식으로 시작 시점으로 바꾼다. 10년 대운, 연별 세운, 절기 경계의 월운을 생성한다.
5. **검증과 렌더:** `계산 기준 버전`, `시간 보정 방식`, `경계 시각`, `입력 정확도`를 결과와 함께 저장한다. 표로 보여주고 화면의 PNG 저장 버튼을 만든다. GPT에는 이미지보다 검증된 **구조화 JSON**을 전달해 풀이만 맡긴다. 별도로 기존 만세력 사진을 읽는 기능은 유지할 수 있다.

## 후보 소스와 부족한 점

- [한국천문연구원 음양력 정보 API](https://www.data.go.kr/data/15012679/openapi.do): 양·음력 대응, 윤달, 세차·일진 등을 제공한다. 서비스키가 필요하다. 만세력의 십성·대운 계산 결과를 통째로 제공하는 API는 아니다.
- [한국천문연구원 특일 정보 API](https://www.data.go.kr/data/15012690/openapi.do): 24절기를 제공하나 포털에 공개된 응답 항목은 `locdate`(날짜)·`dateName`(명칭) 등이다. **절입의 시·분 정보가 없으므로** 이 API만으로 절기 당일 출생자의 월주를 정확히 판정할 수 없다. 시각 정밀도의 별도 천문 자료나 검증된 역법 엔진이 필요하다.
- [6tail/lunar-javascript](https://github.com/6tail/lunar-javascript): MIT 라이선스의 자바스크립트 음양력·팔자 라이브러리. `Solar.fromYmdHms(...).getLunar().getEightChar()`와 `getYun(gender)` 같은 계산 기능이 있다. 채택 전 한국의 실제 출생 시각·시간대 및 선택한 전통 나이 규칙과의 일치 여부를 검증해야 한다. 라이브러리 결과를 국내 모든 앱의 유일한 정답으로 취급하지 않는다.

## 첨부 화면을 통한 예비 검증

로컬에서 `lunar-javascript@1.7.7`의 네 기둥을 캡처의 다섯 사례와 비교했다. **4개는 시·일·월·년주 모두 일치**했고, 1개는 출생시각이 정확히 **21:00**인 경우 시주에서만 차이가 났다. 표준시 그대로 계산하면 亥시, 캡처에는 戌시가 표시된다. 출생지에 따른 약 30분의 시각 보정을 가정하면 戌시가 가능하지만, 다른 경계 사례까지 일관되게 재현되는지 알 수 없으며 앱의 설정값도 보이지 않는다. 이 보정은 **가설**이지 해당 앱의 내부 구현에 대한 확인이 아니다.

정수로 표시된 대운수도 라이브러리에서 얻는 `몇 년 몇 개월 며칠`과 비교하면 대체로 반올림 또는 최소 1세 처리처럼 보이지만, 각 앱의 대운 계산 유파와 나이 표시 방식을 확인하기 전에는 동일 구현을 단정하지 않는다.

## 자체 엔진 구현 전에 확정할 것

1. 한국 출생에 적용할 표준시/역사적 시간대와 출생지 보정의 기본값 및 선택 옵션.
2. 자시 23:00 이후의 일주 교체 규칙과 절입 시각 자료의 정확도.
3. 대운 기산 방식(3일=1년 등), 순·역행, 시작 연령의 표시 방식.
4. 오행 개수에 지장간을 포함할지(첨부 화면은 8글자 기준으로 보임), 신살/귀인 규칙의 출처와 버전.
5. 한국천문연구원 양음력 결과와 독립 역법 엔진을 입춘·절입·윤달·자시 경계의 여러 테스트에서 교차 검증.

이 기준이 정해지면 날짜 입력 → 자체 만세력 생성 → 이미지 다운로드 → 구조화된 명식의 AI 해석 순으로 기존 이미지 업로드 흐름을 확장한다.
